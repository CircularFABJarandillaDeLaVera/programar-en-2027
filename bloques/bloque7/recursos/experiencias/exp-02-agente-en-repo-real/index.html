EXP-02 · 60-90 min · Registro de participantes

Preparar un cambio

Aprende a entender un problema, aclarar objetivo y límites, preparar criterios de aceptación y proponer un plan antes de modificar código.

El agente ayuda a preparar el trabajo; tú revisas la ficha, autorizas el alcance, inspeccionas el diff y decides.

Antes de empezar

En EXP-01 has trabajado con el inventario del taller y su arnés de bolsillo. Ahora cambiamos de proyecto: vamos a corregir un registro de participantes con ayuda de un agente.

Conserva la carpeta del inventario. Para esta experiencia abre una carpeta nueva.

1. PREPARAR · descarga y abre el proyecto

Descargar el registro de participantes · EXP-02–04

  1. Extrae el ZIP completo en una carpeta nueva, conservando .agents/.
  2. Abre esa carpeta mediante Archivo > Abrir carpeta en VS Code.
  3. Comprueba que contiene app.py, participantes.py, test_participantes.py, README.md y AGENTS.md, además de la skill.
  4. Abre una terminal allí y continúa con la ejecución inicial.

Esta misma carpeta se reutiliza en EXP-03 y EXP-04. Antes de proponer git init, comprueba si ya existe un repositorio; Git es un punto de control útil, pero no un requisito para acceder ni practicar.

2. OBSERVAR · ejecuta el fallo real

En la terminal abierta en esa carpeta, ejecuta python app.py. Introduce Nombre: Luis y Edad: -15. La salida inicial es Participante registrado: Luis (-15 años). Todavía no está corregido.

3. PREPARAR EL CAMBIO CON EL AGENTE

El agente lee las instrucciones, el README y los archivos Python; después prepara objetivo, evidencia, alcance, criterios y plan, y se detiene antes de editar.

Petición inicial

Quiero corregir el registro de participantes porque acepta edades negativas. Ayúdame a preparar el cambio antes de tocar código.

Usa la skill incluida en .agents/skills/preparar-cambio/SKILL.md o invócala con $preparar-cambio si tu instalación reconoce esa sintaxis.

4. REVISAR Y AUTORIZAR

Objetivo

Rechazar edades fuera de 0–120.

Alcance

Si el plan lo confirma, limitar la corrección a participantes.py.

Aceptación

-15 devuelve el error esperado y una edad válida se registra.

Comprobaciones

Prueba manual, tests, estado y diff; marca lo no ejecutado como NO_VERIFICADO.

Autoriza solo después de revisar la ficha y el plan:

He revisado la ficha y el plan. Autorizo únicamente el alcance descrito: corregir la validación de edad en participantes.py, conservar app.py y las pruebas, y no añadir dependencias. Aplica el plan y después informa de lo comprobado y lo pendiente.

5. COMPROBAR Y DECIDIR

Después de la autorización, comprueba git status, git diff, python app.py y python -m unittest -v.

unittest forma parte de Python. Un fallo del detector de pruebas del editor no demuestra que las pruebas no existan. Si no hay Git, no lo inicialices automáticamente ni finjas disponer de git diff: compara antes/después si conservaste el original y declara la limitación si no es posible.

Después informa del archivo modificado, las líneas cambiadas, las comprobaciones y sus resultados, y lo que siga sin verificarse. ACEPTA, AJUSTA o DESCARTA según la evidencia.

6. PEQUEÑA AMPLIACIÓN · edad = 120

Como cambio separado, puedes autorizar únicamente una prueba para confirmar que edad = 120 es válida. No mezcles este cambio con la corrección de participantes.py.

7. GUARDAR Y CONTINUAR

Conserva la versión validada siguiendo el procedimiento autorizado. Continúa a EXP-03 con esta misma carpeta.

8. LLEVAR LA SKILL A OTRO PROYECTO

La skill independiente es opcional para otros proyectos: el ZIP del registro ya la incluye y no la necesitas para empezar EXP-02.

Descargar la skill independiente · Preparar un cambio

Extrae el ZIP en otro proyecto conservando .agents/skills/preparar-cambio/SKILL.md; si ya existe una skill con ese nombre, compara ambas antes de reemplazarla.
