El agente entra en un repositorio real

Objetivo: aprender a dirigir un agente que trabaja sobre un repositorio — no a aprender una herramienta. El gesto (contexto → PLAN → autorización → cambio pequeño → diff → decisión) funciona igual con OpenCode, Codex, Copilot, Claude Code u otro.

abrir repo → leer AGENTS.md → explicar objetivo → QUIERO/NO QUIERO → PLAN → autorizar → 1 cambio → ejecutar → git diff → ACEPTAR/MODIFICAR/RECHAZAR

PREPARAR

Descargar proyecto B7-Agente-Real

Descarga el ZIP, descomprímelo en tu carpeta de trabajo y abre esa carpeta en tu agente. Esta misma copia te acompaña en EXP-02, EXP-03 y EXP-04: no la descargues tres veces. Estructura (mírala, no la memorices):

agente-real/
├── app.py                # entrada del programa
├── participantes.py      # lógica (contiene el fallo)
├── test_participantes.py # pruebas automáticas
├── README.md             # guía del proyecto
└── AGENTS.md             # instrucciones permanentes para el agente

Prepara tu red de seguridad (de B6 ya sabes qué hace cada comando):

git init
git add app.py participantes.py test_participantes.py README.md AGENTS.md
git commit -m "inicio: practica de agentes"

VER (el repo es la verdad)

Antes de pedir nada al agente: abre el repo correcto, lee AGENTS.md entero y ejecuta el fallo con tus manos:

python app.py
Nombre: Luis
Edad: -15

Si ves Participante registrado: Luis (-15 años), has visto el fallo real. Anota en una frase: qué archivo lo produce y qué comportamiento observas. Todavía no pidas nada.

PROBAR — el agente analiza, tú no autorizas todavía

Explica al agente el objetivo y pide SOLO análisis. Nada de código todavía:

Analiza este proyecto y localiza por qué permite registrar edades negativas.
No modifiques ningún archivo todavía.

Explícame:
1. dónde está el problema;
2. qué comportamiento produce;
3. qué archivo necesitarías modificar para corregirlo.

Lee el análisis con ojo crítico: ¿señala participantes.py? ¿menciona que falta validar el rango 0-120? Si el análisis es correcto, pasa a autorizar. Si no, pide que lo precise. Analizar no es autorizar.

MODIFICAR — autoriza UN cambio pequeño

Delimita el alcance por escrito antes de autorizar:

QUIERO: rechazar edades fuera de 0-120 (ambos incluidos) con el mensaje
"Error: la edad debe estar entre 0 y 120 años.".
NO QUIERO: nuevas dependencias, tocar app.py, tocar pruebas,
ni ninguna otra mejora.

Pide PLAN primero y dale tu OK (OK - seguir / NO - ajustar: …). Solo entonces autoriza:

Corrige el problema según el plan aprobado.
Modifica únicamente los archivos estrictamente necesarios.
Después explica exactamente qué has cambiado.

Revisa lo que hace el agente y decide. El flujo de verificación es:

git status
git diff
python app.py
python -m unittest -v

Preguntas que debes responder por escrito: ¿qué archivos tocó (status)? ¿cambió solo lo necesario (diff)? ¿el caso Luis/-15 ya se rechaza? ¿las 3 pruebas terminan en OK? Si algo no cuadra, no aceptes: pide que lo reduzca.

MINI-RETO (autonomía)

Sin pasos detallados: pide al agente que añada UNA prueba automática nueva para el borde edad = 120 (válida) sin tocar la lógica. Revisa el diff: si modifica algo más que el archivo de pruebas, rechaza y reduce el alcance.

RESULTADO OBSERVABLE

Demuestras el gesto completo en tu terminal:

# 1. El caso real ya se rechaza:
Nombre: Luis / Edad: -15
Error: la edad debe estar entre 0 y 120 años.
# 2. Solo cambió lo autorizado:
git status            # p. ej. solo participantes.py
git diff              # líneas coherentes con lo pedido
# 3. Nada se rompió:
python -m unittest -v # 3 tests -> OK
# 4. Tu decisión escrita: ACEPTO / MODIFICO / RECHAZO + motivo en 2 líneas.

Si el agente no pudo ejecutar Python en su entorno, dilo así: NO_VERIFICADO en su comprobación, y la verificación real la haces tú en tu terminal. “La IA dice que funciona” no es evidencia.

COMPROBAR

git status
git diff
python app.py
python -m unittest -v

Checklist de salida: ¿AGENTS.md leído? ¿objetivo explicado al agente? ¿QUIERO/NO QUIERO escritos? ¿PLAN pedido y autorizado con OK? ¿1 cambio pequeño? ¿diff revisado línea a línea? ¿decisión justificada?

PLAN B (sin red / sin agente)

Sin agente: tu compañero actúa como “agente con harness”. Tú le entregas por escrito objetivo + QUIERO/NO QUIERO + criterios; él te devuelve primero un PLAN en papel y, tras tu OK escrito, un diff de 5-10 líneas. Tú ejecutas, pruebas y decides. Sin PowerShell: vale CMD con los mismos comandos.

CONTINUAR

Frase de cierre: “sé abrir un repo, dar contexto, pedir plan, autorizar un cambio pequeño y revisar el diff antes de decidir”. Guarda tu cambio validado con un commit. No borres esta copia: la reutilizas en EXP-03 y EXP-04. Siguiente: EXP-03.
