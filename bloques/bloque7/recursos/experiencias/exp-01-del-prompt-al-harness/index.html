EXP-01 · Del prompt al arnés

Del prompt al arnés

Vas a pedir dos cambios a un programa de inventario, revisar lo que propone un agente y usar un comprobador para detectar errores y regresiones.

1. Qué vas a hacer

Trabajarás con un inventario de taller. Primero verás cómo funciona; después pedirás al agente dos cambios concretos; por último ejecutarás un comprobador para saber qué se cumple y qué se rompe.

Estos son los cuatro archivos del proyecto:

  • inventario_taller.py: el proyecto, un programa que carga piezas, las añade, calcula su valor y guarda el inventario.
  • datos_ejemplo.json: cinco piezas de ejemplo que usa el programa y el comprobador.
  • comprobar.py: el arnés. Ejecuta comprobaciones repetibles sobre comportamientos concretos e informa de su estado.
  • chuleta-harness.md: una guía breve para pedir, revisar y comprobar cambios con ayuda de un agente.

Un agente es un asistente de programación que propone y modifica código bajo dirección humana. El arnés ayuda a comprobar; no sustituye leer el cambio, revisar el diff ni decidir si lo aceptas.

2. Preparar la carpeta

  1. Pulsa Descargar proyecto-b7-harness.zip.
  2. Crea una carpeta propia, por ejemplo mi-arnes-b7, y extrae dentro el ZIP. Debe quedar una carpeta plana con estos cuatro archivos: inventario_taller.py, datos_ejemplo.json, comprobar.py y chuleta-harness.md.
  3. Abre esa carpeta en VS Code: Archivo → Abrir carpeta….
  4. Abre Terminal → Nueva terminal. Comprueba que la terminal está situada en la carpeta que contiene los cuatro archivos. En PowerShell puedes escribir dir y comprobar que aparecen sus nombres.

El proyecto usa solo Python y su librería estándar. No instales dependencias ni crees entornos para esta práctica.

3. Ejecutar el inventario

Lee inventario_taller.py y después ejecuta el programa:

python inventario_taller.py

Debería aparecer una línea por cada pieza y este total:

Broca 5mm | 10.0 | 20
Tornillo M4 | 2.0 | 5
Placa base | 50.0 | 10
Filamento PLA | 25.0 | 12
Sensor DHT22 | 8.0 | 0
Total: 1010.0

Esto significa que el programa se ejecutó y calculó el inventario actual. Todavía no has comprobado si cumple las reglas nuevas. Ejecutar el programa y ejecutar comprobar.py son acciones distintas.

4. Ejecutar el diagnóstico

Ahora ejecuta el arnés:

python comprobar.py

El resultado inicial real resume seis comprobaciones:

[APTO] carga_ejemplo: se cargan 5 piezas
[NO_APTO] descuento_stock_alto: total 1010.0, se esperaba 960.0
[APTO] borde_stock_10: stock 10 sin descuento: 500.0
[NO_APTO] valida_entradas: acepta entradas invalidas: Mala1, Mala2
[APTO] guardar_cargar: el JSON guardado carga identico
[NO_VERIFICADO] rendimiento_volumen: no probado con miles de piezas; pendiente de comprobar, no es fallo

Resumen: 3 APTO, 2 NO_APTO, resto NO_VERIFICADO.

Los dos fallos deliberados de partida son descuento_stock_alto y valida_entradas. Son el trabajo que vas a pedir al agente. El caso rendimiento_volumen queda NO_VERIFICADO porque comprobar.py dice exactamente que no se ha probado con miles de piezas. No es un caso superado ni un fallo: sigue pendiente.

5. Pedir un plan al agente

Copia este prompt en tu agente. Pide primero un plan: leer el plan no autoriza todavía a modificar archivos.

Lee estos tres archivos antes de responder: inventario_taller.py, comprobar.py y datos_ejemplo.json. También puedes consultar chuleta-harness.md para seguir el procedimiento.

Necesito mejorar únicamente inventario_taller.py con estas dos reglas:

1. En valor_total, aplicar un descuento del 10 % al valor de cada pieza cuyo stock sea estrictamente mayor que 10. Si el stock es 10, no se aplica el descuento.
2. En anadir_pieza, rechazar un precio negativo o un stock negativo lanzando ValueError. Las entradas no negativas deben seguir funcionando.

Límite: solo puedes modificar inventario_taller.py. No modifiques comprobar.py, datos_ejemplo.json, chuleta-harness.md ni los resultados esperados para hacer pasar las comprobaciones. No añadas dependencias ni cambies otras funciones sin justificarlo.

Antes de editar, propón un plan breve que indique qué vas a cambiar y cómo comprobarás cada regla. No escribas ni modifiques código todavía. Después del plan, espera mi autorización explícita.

Cuando autorice el plan, aplica los cambios, explica qué has cambiado y ejecuta python inventario_taller.py y python comprobar.py para comprobar el resultado.

Revisa el plan: debe mencionar valor_total, la condición estricta stock > 10, anadir_pieza, ValueError y el límite de un solo archivo. Si propone editar el comprobador o los datos, corrige el plan antes de continuar.

Autoriza solo cuando estés de acuerdo:

Autorizo este plan. Aplica ahora los cambios únicamente en inventario_taller.py.

6. Revisar y comprobar

Cuando el agente termine, abre el control de código fuente de VS Code y revisa el diff de inventario_taller.py. Debes reconocer estas dos reglas: descuento del 10 % solo con stock > 10; ValueError para precio o stock negativos. El comprobador, los datos y los resultados esperados deben seguir intactos.

Guarda el archivo con Ctrl+S. Ejecuta de nuevo:

python inventario_taller.py
python comprobar.py

El inventario debe mostrar ahora Total: 960.0. El comprobador debe mostrar:

Resumen: 5 APTO, 0 NO_APTO, resto NO_VERIFICADO.

En total: 5 APTO, 0 NO_APTO y 1 NO_VERIFICADO.

Los cinco criterios comprobables están APTO. Mantén visible rendimiento_volumen como NO_VERIFICADO: el arnés no ha probado miles de piezas y eso sigue pendiente.

7. Provocar una regresión controlada

Hazlo solo después de tener las dos correcciones aplicadas y el resultado anterior. En valor_total, cambia temporalmente:

if pieza["stock"] > 10:

por:

if pieza["stock"] >= 10:

Guarda y ejecuta:

python comprobar.py

El resultado real debe ser 3 APTO, 2 NO_APTO y 1 NO_VERIFICADO. Fallan descuento_stock_alto y borde_stock_10.

Qué ha pasado: los stocks 20 y 12 cumplen las dos condiciones, así que no cambian. La Placa base tiene stock 10 y ahora recibe indebidamente el descuento: su valor pasa de 500.0 a 450.0. Por eso el total agregado pasa de 960.0 a 910.0. El arnés detecta el problema tanto en el total (descuento_stock_alto) como en el caso aislado de borde (borde_stock_10).

Es una regresión válida: el programa sigue siendo sintácticamente correcto, pero cambió el significado de la regla. No edites comprobar.py.

8. Restaurar y cerrar

Restaura la condición estricta:

if pieza["stock"] > 10:

Guarda y comprueba la recuperación:

python comprobar.py

Debe volver a aparecer 5 APTO, 0 NO_APTO y 1 NO_VERIFICADO. Para cerrar, responde brevemente:

  1. ¿Qué cambió el agente?
  2. ¿Qué error detectó el arnés?
  3. ¿Qué sigue sin comprobarse?
