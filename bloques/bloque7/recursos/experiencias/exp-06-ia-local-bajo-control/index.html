EXP-06 · 60-90 min · Ollama opcional, nunca requisito · Tú controlas lo no determinista

IA local bajo control

Objetivo: integrar una IA sin entregarle el control del programa. Esto no es un curso de Ollama: Ollama es un backend real opcional. Toda la competencia se completa sin él.

Python → llama al modelo si está disponible → valida estructura → valida contenido → acepta o rechaza → fallback determinista

PREPARAR

Descargar proyecto B7-IA-Control

Descarga el ZIP, descomprímelo y abre PowerShell dentro de ia-control/.

ia-control/
├── explicar.py                       # decide, llama, valida, fallback
├── test_explicar.py                  # pruebas sin red ni Ollama
├── ejemplo-respuesta-valida.json     # modelo simulado: se acepta
├── ejemplo-respuesta-inventada.json  # modelo simulado: se rechaza
├── requirements.txt                  # requests (opcional)
└── README.md                         # guía del proyecto

No instales nada para empezar. La Ruta B (sin IA) es la primera y es completa.

VER — Python decide, la IA solo explica

Lee explicar.py y localiza las 3 responsabilidades (están separadas a propósito):

decidir()            # Python: regla determinista (stock/minimo -> decisión)
validar_respuesta()  # Python: estructura + contenido de lo que diga el modelo
explicar()           # Python: orquesta llamada, validación y fallback

Ejecuta la Ruta B y observa que el sistema ya funciona sin ningún modelo:

python explicar.py --stock 3 --sin-ia
python -m unittest -v

Deberías ver la decisión PEDIR_MATERIAL con origen DETERMINISTA (--sin-ia) y las pruebas en verde. Explica en una frase: ¿quién decidió y quién explicó?

PROBAR — aceptada frente a rechazada (sin Ollama)

Simula dos respuestas de modelo sin necesitar Ollama. Python las juzga:

python explicar.py --stock 3 --demo-respuesta ejemplo-respuesta-valida.json
python explicar.py --stock 3 --demo-respuesta ejemplo-respuesta-inventada.json

Verás RESPUESTA ACEPTADA en el primer caso y RESPUESTA DESCARTADA con FALLBACK DETERMINISTA en el segundo. Abre los dos JSON y localiza TÚ por qué uno pasa y el otro no (pista: cifras permitidas y términos prohibidos). El programa sigue funcionando en ambos casos.

MODIFICAR — endurce el control

Elige UNA (pide PLAN al agente si quieres, el criterio lo pones tú):

Opción A: añade un término prohibido nuevo a TERMINOS_PROHIBIDOS
y una prueba que demuestre que ahora se rechaza.

Opción B: cambia la regla decidir() (p. ej. nuevo umbral) y actualiza
las pruebas y los ejemplos demo para que sigan siendo coherentes.

Verifica:

python -m unittest -v
python explicar.py --stock 3 --sin-ia

RUTA A — Ollama real (opcional, solo si te apetece)

ollama pull llama3.2:1b
ollama serve
pip install -r requirements.txt
python explicar.py --stock 3

Si Ollama responde, verás su explicación validada… o descartada con fallback si inventa cifras. Si no responde, el programa informa y usa el fallback: eso es opcional/no ejecutado, nunca un fallo. Clasificación correcta: solo es NO_VERIFICADO si exigías una comprobación concreta y no pudiste hacerla; nunca llames NO_APTO a algo porque Ollama no arranca.

MINI-RETO (autonomía)

Sin pasos detallados: fabrica tu propio mi-respuesta.json que intente colar una cifra inventada pareciendo válida. Ejecútalo con --demo-respuesta y demuestra que Python la rechaza. Explica qué regla la cazó.

RESULTADO OBSERVABLE

Demuestras las 4 situaciones en tu terminal:

# 1. Salida válida → aceptada (demo-respuesta válida)
# 2. Salida inventada/inválida → rechazada + fallback (demo inventada)
# 3. Modelo no disponible → fallback, el programa sigue (--sin-ia)
# 4. (Opcional) Ollama real → aceptada o descartada, siempre validada

Y defiendes la idea: la IA genera lenguaje; Python decide, valida y responde. Si no puedes explicar qué validó tu programa, no está terminado.

COMPROBAR

python -m unittest -v
python explicar.py --stock 3 --sin-ia
python explicar.py --stock 3 --demo-respuesta ejemplo-respuesta-valida.json
python explicar.py --stock 3 --demo-respuesta ejemplo-respuesta-inventada.json

Checklist de salida: ¿decidir/validar/orquestar localizados? ¿4 situaciones demostradas? ¿1 endurecimiento hecho por ti con prueba? ¿clasificación APTO/NO_VERIFICADO aplicada a Ollama sin llamarlo NO_APTO?

PLAN B (sin red / sin Ollama / sin requests)

Todo lo anterior funciona sin red, sin Ollama y sin instalar nada: --sin-ia y --demo-respuesta solo usan la librería estándar. Si requests no está instalado, la llamada real a Ollama informa y cae al fallback; las pruebas siguen en verde. En papel: clasifica 3 respuestas impresas (válida / cifra inventada / término prohibido) contra las reglas de validar_respuesta.
