EXP-04 · 60-90 min · Reutiliza tu copia de EXP-03 · Tú defines los criterios

Refactor, pruebas y diff

Objetivo: hacer un cambio algo mayor sin aceptar automáticamente lo que produzca el agente. Detectarás al menos una situación en la que propone demasiado — y la reducirás.

QUIERO/NO QUIERO → criterios → PLAN → autorización → cambio → tests → git diff → revisión crítica → ACEPTAR/MODIFICAR/RECHAZAR

PREPARAR

Reutiliza tu misma copia de agente-real/ (edad + nombre ya validados, con sus commits). Parte de un árbol limpio:

git status
python -m unittest

El cambio de hoy es mayor: extraer la validación a funciones pequeñas y dejar pruebas que cubran edad y nombre. Define TÚ los criterios de aceptación antes de abrir el agente (escríbelos, no los improvises).

VER — define el alcance y los criterios

Lee participantes.py entero y escribe tu ficha (este es el trabajo que no se delega):

QUIERO: extraer validar_edad y validar_nombre como funciones pequeñas;
mantener los mismos mensajes de error; cubrir con pruebas
edad válida / edad -15 / edad 130 / borde 0 / borde 120 /
nombre válido / nombre vacío / nombre con números.
NO QUIERO: cambiar mensajes, tocar app.py, añadir dependencias,
eliminar pruebas existentes, ni "mejoras" no pedidas.

Criterios: todas las pruebas existentes siguen en verde · las nuevas pruebas pasan · el comportamiento manual no cambia · el diff solo toca participantes.py y test_participantes.py.

PROBAR — pide PLAN y autoriza

Pide PLAN antes de código, con tu ficha como contexto. Autoriza con tu OK escrito. Solo entonces deja que implemente. Hasta aquí, el gesto ya lo conoces: lo nuevo viene en la revisión.

python -m unittest -v

Si todo está en verde, no celebres todavía: el verde no demuestra que el cambio sea el pedido. Falta la revisión crítica.

MODIFICAR — revisión crítica del diff (el corazón de EXP-04)

Ejecuta y lee línea a línea:

git status
git diff

Busca activamente estas 3 desviaciones típicas de un agente (hay al menos una casi siempre):

1. Cambió demasiado: tocó app.py, README o AGENTS.md sin permiso.
2. Añadió algo innecesario: dependencias, helpers no pedidos,
   validaciones "extra" o cambios de mensajes.
3. Propuso una solución que debe reducirse: reescribió el archivo
   en vez de extraer 2 funciones pequeñas.

Por cada hallazgo decide: se queda / se retira / se reduce. Si hay que reducir, ordénalo así: Retira X y deja solo lo pedido en Y. No toques nada más. Vuelve a ejecutar pruebas tras cada reducción. Documenta al menos UN hallazgo real en tu ficha: qué propuso, por qué sobraba y qué decidiste.

MINI-RETO (autonomía)

Sin pasos detallados: pide al agente que añada el borde edad = 0 como prueba nueva. Antes de aceptar, responde por escrito: ¿el diff es mínimo? ¿los mensajes siguen intactos? ¿entiendes cada línea que se integra?

RESULTADO OBSERVABLE

Entregas tres evidencias:

# 1. Comportamiento idéntico, código más claro:
python -m unittest -v   # todas en verde, incluidas las nuevas
# 2. Diff revisado y reducido por ti:
git diff                # solo participantes.py + test_participantes.py
# 3. Tu ficha: 1 hallazgo real (qué sobraba + tu decisión) y
#    tu veredicto: ACEPTO / MODIFICO / RECHAZO + motivo.

Frase que debes poder defender: “No acepto código porque lo escribió una IA; acepto un cambio porque cumple mis criterios y lo he comprobado.”

COMPROBAR

python -m unittest -v
git status
git diff

Checklist de salida: ¿criterios escritos por ti antes del agente? ¿PLAN autorizado? ¿tests en verde? ¿diff leído línea a línea? ¿≥1 hallazgo documentado con decisión? ¿cada línea integrada es explicable por ti?

PLAN B (sin red / sin agente)

Sin agente: trabaja con un diff impreso que incluya 2 desviaciones (un cambio en app.py no pedido + un helper innecesario). Márcalas, escribe la orden de reducción y aplica tú el refactor a mano. Verifica con pruebas y diff final mínimo.
