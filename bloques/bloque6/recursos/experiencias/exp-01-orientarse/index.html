EXP-01 · 30-45 min · Sin red · Sin instalar nada

Abre y oriéntate en un proyecto Python

abrir raíz → terminal → quién soy (pwd + python) → arrancar → romper la carpeta → localizar función → entrada → función → salida

PREPARAR

Descargar proyecto B6

Descarga el proyecto B6, descomprímelo en tu carpeta de trabajo y utiliza esa misma copia durante las seis experiencias.

La base está en ../proyecto-seguro/ (copia de SAMI-Local; el canónico no se toca). Cópiala una sola vez a tu carpeta de trabajo, por ejemplo mi-proyecto-b6/: esa copia personal te acompaña durante EXP-01→06. Estructura (mírala, no la memorices):

proyecto-seguro/
├── main.py · config.json · requirements.txt · .gitignore
├── data/datos_hardware.csv
└── src/ (analizador, persistencia, generador_pdf, scraper)

Abre VS Code en tu copia personal (mi-proyecto-b6/: la carpeta, no un archivo suelto) y abre su terminal integrada.

VER

Lee main.py entero (20 líneas). Fíjate en dos cosas: las rutas están escritas como "config.json" y "data/..." (relativas), y los imports dicen from src..... Eso significa que la carpeta desde donde ejecutas importa.

pwd
dir

Debes ver main.py en el listado. Si no lo ves, no estás en la raíz. Todo lo que sigue se ejecuta desde aquí.

PROBAR

Pregunta quién eres antes de arrancar:

python --version
python -c "import sys; print(sys.executable)"

Anota las dos respuestas: versión + ruta del intérprete. Ese es tu Python en esta sesión.

Ahora arranca el proyecto desde la raíz:

python main.py

Hay dos salidas honestas y las dos enseñan:

# Si el equipo tiene las dependencias:
  tabla + informe en consola.

# Si falta pandas (normal en EXP-01, se resuelve en EXP-02):
  ModuleNotFoundError: No module named 'pandas'

Si ves el error, no es un fracaso: acabas de descubrir que saber qué intérprete usas incluye saber qué tiene instalado. Sigue: la sonda de abajo funciona sin instalar nada.

python -c "from src.persistencia import cargar_configuracion; print(cargar_configuracion('config.json'))"

Deberías ver {'iva': 0.21, 'stock_minimo': 3}. Acabas de ejecutar código del proyecto sin instalar nada.

MODIFICAR (la carpeta, no el código)

Sin tocar ningún archivo, cambia de carpeta y repite la sonda:

cd src
python -c "from src.persistencia import cargar_configuracion; print(cargar_configuracion('config.json'))"
cd ..

Verás ModuleNotFoundError: No module named 'src'. Vuelve a la raíz con cd .. y la sonda vuelve a funcionar. Todavía no has modificado código y ya sabes la lección central: el mismo comando funciona o falla según la carpeta de trabajo, porque las rutas y los imports son relativos a ella.

RESULTADO OBSERVABLE

La competencia de EXP-01 no es “el proyecto arranca”. Es: sé ejecutar el proyecto desde la raíz correcta y distinguir de dónde viene un fallo:

# Error desde src/ → problema de CARPETA DE TRABAJO (rutas e imports relativos):
ModuleNotFoundError: No module named 'src'
# Error "No module named 'pandas'" desde la raíz → DEPENDENCIA PENDIENTE (no es tu culpa):
ModuleNotFoundError: No module named 'pandas'

Si ves lo segundo, no instales nada todavía: EXP-02 resolverá entorno + requirements.txt. Lo demuestras en tu terminal:

# 1. Estoy en la raíz (ves main.py):
dir
# 2. Sé qué Python ejecuto:
python -c "import sys; print(sys.executable)"
# 3. Ejecuto desde la raíz y clasifico el fallo (carpeta / intérprete / dependencia):
python main.py
# 4. Localizo código sin haberlo roto (nada modificado):
#    src/analizador.py → filtrar_stock_bajo(tabla, stock_minimo) → tabla filtrada

COMPROBAR

Checklist de salida (todo con evidencia de terminal, nada de memoria):

[ ] dir muestra main.py (estoy en la raíz)
[ ] python --version + sys.executable anotados
[ ] python main.py ejecutado (arranca o ModuleNotFoundError explicado)
[ ] sonda de config en verde desde la raíz y en rojo desde src/
[ ] una función localizada: archivo + nombre + entrada → salida en una frase
[ ] cero archivos modificados en tu copia personal/
