EXP-06 · 30-45 min · Sin red · Solo repo local (sin push)

Revisa tu cambio y déjalo registrado con Git

Mirar exactamente qué cambiaste antes de guardarlo y dejar un punto identificable. Git aquí es herramienta de trabajo, no teoría.

status → diff → comprobar → add → diff --cached → commit → status + log

Regla de hoy, una sola: antes de guardar un cambio, sé explicar qué estoy guardando.

PREPARAR

Trabajas sobre tu copia personal (mi-proyecto-b6/), la misma de EXP-01. Empieza en estado sano original (stock < stock_minimo), sin venv/ y sin .git/. Confirma la raíz y que .gitignore incluye venv/:

dir

VER

Crea el repositorio local y mira su primer estado:

git init
git status

Verás todos los archivos como nuevos (sin seguimiento). Guarda el punto inicial:

git add .
git status
git commit -m "chore: estado inicial"

Si Git rechaza el commit por falta de identidad, NO toques configuración global. Solo para este repo:

git config user.name "Alumno Programar 2027"
git config user.email "alumno@python2027.local"

Repite el commit. Es configuración LOCAL del repositorio, no de tu máquina. Comprueba:

git status

Debe decir árbol limpio. Ese es tu ANTES.

PROBAR

Repite el cambio funcional de EXP-05 en src/analizador.py (< → <=). Y ANTES de hacer add, revisa:

git status
git diff

Localiza en el diff: el archivo, la línea eliminada (-), la línea añadida (+) y el cambio exacto (un carácter). Di en voz alta: “solo quiero este cambio”.

Verifica antes del commit con lo aprendido en EXP-05 (entorno activo): caso normal (umbral 3 → [RAM-02]), caso borde (umbral 7 → [CPU-01, RAM-02]) y python main.py idéntico. Sin entorno disponible la ejecución queda NO_VERIFICADA: puedes aprender Git, pero no afirmes que el cambio está validado.

MODIFICAR (el registro, no el código)

Prepara únicamente el archivo correcto y revisa exactamente lo que entrará:

git add src/analizador.py
git status
git diff --cached

La diferencia que importa: git diff muestra cambios todavía no preparados; git diff --cached muestra exactamente lo que entrará en el commit. Si aparece algo inesperado (un log, un venv/ colado), NO sigas: revisa primero. Por eso venv/ está ignorado.

git commit -m "fix: incluir stock igual al umbral"

Comprueba el DESPUÉS:

git status
git log --oneline -2

Commit visible + árbol limpio. Pregunta obligatoria: “¿has hecho push?” Respuesta: NO — no hay remoto ni lo necesitas. Tu commit vive en el repositorio local.

MINI-RETO (autonomía)

Sin pasos detallados. Copia bloques/bloque3/recursos/proyecto/ (SAMI-Lite, stdlib) a tu zona de trabajo fuera del curso y copia también el .gitignore de la base (../../proyecto-seguro/.gitignore, ya excluye __pycache__/ y venv/: comprueba con git status que no aparecen). Haz el ciclo completo sobre tu copia: repo + commit inicial, cambia evaluar_alerta_precio de > a >=, revisa el diff, comprueba con python -c (borde + 2 casos), añade solo el archivo, revisa --cached, commit y demuestra árbol limpio. Nunca hagas git add . a ciegas.

RESULTADO OBSERVABLE

ANTES:      git status limpio (commit "chore: estado inicial")
CAMBIO:     git diff con 1 línea (- <, + <=)
VERIFICACIÓN: casos normal/borde + main.py (o NO_VERIFICADA honesta)
PREPARADO:  git diff --cached solo con el cambio autorizado
DESPUÉS:    commit "fix: incluir stock igual al umbral" en git log + status limpio
PUSH:       no hecho; el commit está en local

Y en menos de 60 segundos: “revisé el diff antes de guardar el cambio, comprobé su comportamiento y dejé un commit local identificable”.

COMPROBAR

[ ] .gitignore revisado (venv/ ignorado)
[ ] commit inicial + status limpio (ANTES)
[ ] git diff localizado (archivo, - , + , cambio exacto)
[ ] verificación funcional antes del commit (o NO_VERIFICADA)
[ ] git add solo de src/analizador.py
[ ] git diff --cached == solo el cambio autorizado
[ ] commit fix visible en git log --oneline -2 + status limpio
[ ] explico commit (local) vs push (remoto, no hecho aquí)

PLAN B (sin git / identidad / archivos raros)

Sin git instalado: trabaja sobre un diff real preparado (el de esta página vale), identifica añadido/eliminado y decide si lo aceptarías; los comandos quedan NO_VERIFICADOS. Commit rechazado por identidad: configuración LOCAL mostrada arriba, nunca global obligatoria. Archivos inesperados en status: no hagas add . a ciegas; revisa y explica por qué venv/ debe estar ignorado. Sin red: todo lo de hoy funciona offline.

CONTINUAR (cierre de B6)

Antes de terminar, deja en tus notas habituales cinco líneas para poder retomar el proyecto sin adivinar dónde estabas. Escríbelas a partir de lo que acabas de comprobar con git status, git log, la ejecución y las pruebas:

Me quedo en:
Funciona:
Todavía no funciona / no está comprobado:
Decisión importante:
Siguiente paso:

Si algo no se ha podido comprobar, déjalo honestamente como pendiente. Esta nota ayuda a continuar, pero no sustituye a Git, a las pruebas ni a ejecutar el proyecto.

Ya puedes: orientarte → preparar entorno → comprender → depurar → modificar → verificar → registrar. En B7 entra una nueva variable: un agente podrá trabajar contigo dentro del repositorio. No entra todavía: ramas, merge, GitHub, agentes.
