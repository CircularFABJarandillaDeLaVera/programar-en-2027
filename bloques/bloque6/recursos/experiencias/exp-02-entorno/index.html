EXP-02 · 30-45 min · Necesita red para instalar (si no, Plan B)

Tu entorno, tus dependencias

Vienés de EXP-01: desde la raíz correcta, python main.py dice ModuleNotFoundError: No module named 'pandas'. Hoy preparas entorno propio + dependencias declaradas.

raíz → ANTES (python global) → venv → activar → DESPUÉS (python del entorno) → requirements → instalar → main.py → .gitignore

PREPARAR

Trabajas sobre tu copia personal (mi-proyecto-b6/), la misma de EXP-01. Nada del proyecto canónico se toca.

proyecto-seguro/
├── main.py · config.json · data/ · src/
├── requirements.txt   # numpy, pandas, pytest-playwright, reportlab
└── .gitignore         # venv/ y logs/ ya están ignorados (ábelo y compruébalo)

Abre VS Code en proyecto-seguro/ y su terminal integrada. Confirma la raíz:

dir

VER

Antes de crear nada, retrata tu punto de partida (lo compararás al final):

python -c "import sys; print(sys.executable)"
python -m pip --version

La ruta apunta al Python global del equipo. Ahora lee requirements.txt (4 líneas, sin teoría):

numpy
pandas
pytest-playwright
reportlab

Respuesta que debes poder dar: “estas son las dependencias declaradas del proyecto”. Declaradas no significa instaladas: eso lo compruebas ahora.

PROBAR

1. Crea el entorno (una carpeta aislada con su propio Python):

python -m venv venv

2. Actívalo. En CMD:

venv\Scripts\activate

En PowerShell:

.\venv\Scripts\Activate.ps1

Si PowerShell bloquea el script (no se puede cargar…), no cambies nada global del sistema: usa CMD como alternativa inmediata (esta misma terminal puede abrirse como CMD) o ejecuta directamente el Python del entorno (paso 3), que no necesita activación.

3. Demuestra el cambio. Repite el retrato con el entorno activo (o, sin activar, con venv\Scripts\python.exe en lugar de python):

python -c "import sys; print(sys.executable)"
python -m pip --version

La ruta ahora termina en venv\Scripts\python.exe y pip apunta al mismo entorno. Ese ANTES → DESPUÉS es el corazón de la experiencia.

4. Instala lo declarado (siempre con python -m pip, nunca pip a secas):

python -m pip install -r requirements.txt

5. Comprueba al menos una dependencia:

python -c "import pandas; print(pandas.__version__)"

6. Vuelve a arrancar:

python main.py

Clasifica con honestidad: dependencia Python instalada → comprobada. El scraper no se ejecuta aquí y el navegador de Playwright está fuera de alcance de EXP-02 / no requerido aquí (no es NO_VERIFICADO: NO_VERIFICADO se reserva para criterios de esta experiencia que no se hayan podido comprobar). No instales navegadores en esta experiencia.

MODIFICAR (el entorno, no el código)

Abre .gitignore y comprueba que venv/ está en la lista. Explica en una frase, en voz alta o por escrito:

El entorno se reconstruye desde requirements.txt; no se copia dentro del repositorio.

Prueba mental: si borrases venv/ entero, ¿perderías el proyecto? (Respuesta: no; se recrea con los pasos 1-4.) No lo borres en clase salvo que te sobre tiempo: la pregunta basta.

MINI-RETO (autonomía)

Repite con menos instrucciones sobre el proyecto de la EXP08 del Lab: descarga fastapi-participantes.zip desde el Lab Python en Acción, descomprímelo en tu zona de trabajo (fuera del curso) y haz, sin mirar los pasos de arriba:

localizar requirements.txt → crear/activar entorno → comprobar intérprete → instalar → ejecutar

Sus dependencias vienen fijadas (fastapi, uvicorn[standard], httpx). Entrega: sys.executable ANTES y DESPUÉS + salida de ejecutar el proyecto + qué harías sin red (ver Plan B).

RESULTADO OBSERVABLE

Al terminar enseñas, en tu terminal:

# ANTES (Python global):
C:\...\WindowsApps\...\python.exe
# DESPUÉS (Python del entorno):
...\proyecto-seguro\venv\Scripts\python.exe
# pip del mismo entorno:
python -m pip --version
# dependencia comprobada (o NO_VERIFICADA honesta sin red):
python -c "import pandas; print(pandas.__version__)"
# requirements identificado + venv/ en .gitignore

COMPROBAR

[ ] dir desde la raíz (ves main.py + requirements.txt)
[ ] sys.executable ANTES anotado (global)
[ ] venv/ creado (dir lo muestra, .gitignore lo ignora)
[ ] sys.executable DESPUÉS apunta a venv\Scripts\python.exe
[ ] python -m pip --version del mismo entorno
[ ] requirements.txt leído y explicado en una frase
[ ] install ejecutado o clasificado NO_VERIFICADO (sin fingir)
[ ] pandas importado o NO_VERIFICADO + main.py ejecutado y clasificado
[ ] cero comandos Git, cero código modificado

PLAN B (sin red)

Sin red no se finge una instalación correcta. Haz todo hasta el paso 3 (venv creado, activado y demostrado con ANTES → DESPUÉS), inspecciona requirements.txt y muestra el comando que ejecutarías (python -m pip install -r requirements.txt). Clasifica instalación e import como NO_VERIFICADAS y continúa con el entorno que el docente haya provisionado, si existe. La falta de red nunca es un “APTO”.
