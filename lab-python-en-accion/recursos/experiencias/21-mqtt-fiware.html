DEL SENSOR AL CONTEXTO DE LA EMPRESA

DESCARGAR PRÁCTICA

Los datos ya circulan por MQTT. Ahora se necesita convertir ese flujo en contexto actual consultable para la empresa.

La necesidad

MQTT transporta mensajes. FIWARE representa el estado actual que la empresa puede consultar.

MQTT
= MENSAJE EN MOVIMIENTO

FIWARE
= ESTADO ACTUAL CONSULTABLE

La diferencia sigue siendo clara: PostgreSQL conserva el histórico, MQTT mueve mensajes y FIWARE representa contexto actual e interoperable.

Arquitectura del aprendizaje

SIMULADOR PYTHON
      ↓
     MQTT
      ↓
  MOSQUITTO
      ↓
PUENTE PYTHON
      ↓
   FIWARE
      ↓
CONTEXTO ACTUAL
DE LA EMPRESA

El componente nuevo es puente_mqtt_fiware.py. Se suscribe al topic MQTT, valida el JSON, transforma el dato al modelo FIWARE y crea o actualiza la entidad.

Contrato reutilizable

{
  "dispositivo_id": "compostera-cf-01",
  "temperatura_c": 36.8,
  "humedad_pct": 62
}

Topic:

circularfab/dispositivos/compostera-cf-01/telemetria

Suscripción reutilizable:

circularfab/dispositivos/+/telemetria

Modelo FIWARE

La entidad representa el dispositivo como contexto actual:

id: urn:ngsi-ld:Device:compostera-cf-01

type: Device

atributos:
- temperature
- humidity

La práctica reusa el mismo estilo que ya aprendimos con FIWARE en 17 y 18. No añadimos un modelo paralelo ni otro patrón incompatible.

Resultado observable

  1. Terminal A: simulador publicando MQTT.
  2. Terminal B: puente receiving + actualización en FIWARE.
  3. Consulta de Orion-LD: temperatura y humedad del dispositivo.
Dispositivo: compostera-cf-01
Temperatura: 36.8 °C
Humedad: 62 %

Cuando llega otra lectura, el valor cambia sin cambiar el puente.

Ejecutar la práctica

  1. Levanta Mosquitto: docker compose up -d.
  2. Levanta Orion-LD local con la práctica 17/18.
  3. Terminal A: python puente_mqtt_fiware.py.
  4. Terminal B: python simulador_compostera.py.
  5. Consulta FIWARE: curl http://localhost:1026/ngsi-ld/v1/entities/urn:ngsi-ld:Device:compostera-cf-01.
  6. Detén servicios cuando acabes.

Mini-reto

Cambia en el simulador:

dispositivo_id = "compostera-cf-01"

por:

dispositivo_id = "compostera-cf-02"

Comprueba que MQTT sigue funcionando, que el puente recibe el nuevo dispositivo y que FIWARE crea o actualiza otra entidad. El contrato sigue siendo sólido por la clave dispositivo_id.
