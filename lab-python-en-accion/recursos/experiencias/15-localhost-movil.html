Del localhost al móvil

DESCARGAR PRÁCTICA

Objetivo: abrir desde otro dispositivo la aplicación de control horario que se ejecuta en el PC servidor.

La nueva necesidad

Hasta ahora hemos usado la aplicación desde el mismo ordenador donde ejecutamos FastAPI. Ahora queremos abrirla desde un móvil, una tablet u otro PC conectado a la misma red local.

Si ya realizaste la Experiencia 14, reutiliza esa misma práctica. La aplicación no necesita cambios de código para esta prueba.

IP y puerto

Para entrar desde otro dispositivo necesitamos la IP del servidor y el puerto.

192.168.1.X
        +
      8000
        ↓
192.168.1.X:8000

La URL de la práctica será:

http://IP_DEL_PC:8000/app/fichar/

No fijes una IP concreta: cada red tendrá la suya.

Arranque local

uvicorn main:app --reload

Este comando sirve para trabajar desde el propio ordenador. Por defecto, Uvicorn escucha en 127.0.0.1, que es acceso local.

Arranque LAN

uvicorn main:app --reload --host 0.0.0.0
0.0.0.0
≠
URL PARA EL NAVEGADOR

0.0.0.0 significa que Uvicorn escucha en las interfaces de red disponibles. El cliente abre la IP real del servidor.

SERVIDOR ESCUCHA:
0.0.0.0:8000

CLIENTE ABRE:
192.168.1.X:8000

IPv4 en Windows

ipconfig

Busca el adaptador que estás usando realmente: Wi-Fi o Ethernet. Localiza la dirección IPv4.

Alternativa más limpia:

Get-NetIPConfiguration |
Where-Object { $_.IPv4DefaultGateway -ne $null }

No elijas automáticamente interfaces virtuales como WSL, Hyper-V, Docker o VPN.

Windows Firewall

Al aceptar conexiones desde otros dispositivos, Windows puede pedir permiso.

  • Permite únicamente cuando corresponda.
  • Prefiere red privada.
  • No abras puertos indiscriminadamente.
  • No desactives el firewall.

Si funciona en localhost pero no desde otro dispositivo, revisa arranque con --host 0.0.0.0, IP correcta, misma red, firewall, aislamiento de clientes y VPN.

Página y API en el mismo servidor

Cuando abrimos la aplicación desde el móvil, la página que vemos y los fichajes que enviamos se comunican con el mismo PC donde está funcionando FastAPI.

Por eso, en esta práctica no necesitamos configurar nada especial para que la página se comunique con FastAPI.

Geolocalización

En nuestra validación real, el navegador móvil abrió la aplicación, permitió iniciar sesión, permitió fichar y la geolocalización funcionó.

Pero no lo conviertas en una afirmación universal. Las APIs sensibles del navegador pueden depender del navegador, del sistema operativo y de las condiciones de seguridad.

HTTPS sigue siendo importante para despliegues reales y se abordará cuando aparezca una necesidad concreta.

NO RESOLVER UN PROBLEMA QUE TODAVÍA NO TENEMOS.

PRÁCTICA

  1. Arranca primero con uvicorn main:app --reload.
  2. Comprueba localhost desde el PC.
  3. Razona por qué localhost no sirve igual desde el móvil.
  4. Para y vuelve a arrancar con uvicorn main:app --reload --host 0.0.0.0.
  5. Ejecuta ipconfig.
  6. Identifica la IPv4 del adaptador activo.
  7. Prueba desde el propio PC http://IP_DEL_PC:8000/app/fichar/.
  8. Conecta móvil, tablet u otro PC a la misma red.
  9. Abre http://IP_DEL_PC:8000/app/fichar/.
  10. Inicia sesión.
  11. Realiza un fichaje.
  12. Observa si la geolocalización funciona en ese dispositivo.
  13. Explica lo ocurrido.

MINI-RETO

Diagnostica esta situación antes de modificar código:

En mi PC funciona localhost:8000,
pero desde el móvil no abre.

Puedes pedir ayuda a tu agente:

Analiza esta práctica.

En mi PC funciona http://localhost:8000, pero desde el móvil no puedo abrir la aplicación.

Primero ayúdame a diagnosticar el problema sin modificar código.

Comprueba o dime cómo comprobar:
- cómo está arrancado Uvicorn;
- cuál es la IP correcta del PC;
- si ambos dispositivos están en la misma red;
- si Windows Firewall puede estar bloqueando;
- si estoy usando una interfaz virtual;
- si el puerto 8000 es el correcto.

NO modifiques archivos todavía.
UN PROBLEMA TÉCNICO NO SIEMPRE REQUIERE CAMBIAR CÓDIGO.
