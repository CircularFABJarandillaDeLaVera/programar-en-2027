UNA IA QUE EXPLICA, PERO NO DECIDE

DESCARGAR PRÁCTICA

La empresa ya tiene una decisión determinista. Ahora necesita explicarla a una persona con claridad y sin perder control del sistema.

Necesidad antes de tecnología

La decisión ya existe:

REVISAR_TEMPERATURA

Lo que falta es una explicación segura para una persona. No queremos que el modelo invente causas ni cambie la lógica de negocio.

Regla central

LangGraph + reglas deterministas -> DECIDEN
Ollama -> EXPLICA
Python -> VALIDA la explicación

El LLM no decide; no cambia umbrales; no inventa causas ni consecuencias; no sustituye ni a FIWARE ni a LangGraph.

FIWARE / contexto actual
↓

Modelo local

Usamos Ollama localmente con el modelo por defecto:

llama3.2:1b

API por defecto:

http://localhost:11434

No se usa OpenAI, Claude, Gemini ni tokens de pago.

Decision y contexto

El dispositivo sigue siendo el mismo:

urn:ngsi-ld:Device:compostera-cf-01

Con los campos:

temperatura_c
humedad_pct

Y la decisión determinista ya visibles es:

REVISAR_TEMPERATURA

Datos de demostración

{
  "dispositivo_id": "compostera-cf-01",
  "temperatura_c": 48,
  "humedad_pct": 60
}

En este caso el sistema decide:

REVISAR_TEMPERATURA

Por qué no confiamos ciegamente en un LLM

En clase aparece un caso didáctico muy importante:

  • un prompt poco controlado puede inventar “gases tóxicos” o “contaminación del suelo”;
  • un prompt más estricto puede decir “ha superado los 48 °C” cuando el dato es exactamente 48 °C.

Eso no hace al modelo “malo”; simplemente muestra que el LLM genera lenguaje probabilístico. La aplicación debe decidir qué responsabilidad le asigna.

Prompt controlado

El modelo recibe solo datos estructurados y reglas muy concretas:

  • dispositivo
  • temperatura
  • humedad
  • decisión determinista
  • acción determinista permitida

Además se le indica explícitamente:

  • no inventar causas
  • no predecir consecuencias
  • no añadir conocimiento externo
  • no modificar cifras
  • no cambiar la decisión
  • no usar frases como “ha superado 48” si el valor es 48
  • respuesta breve

Salida JSON segura

{
  "explicacion": "...",
  "accion": "..."
}

Si la respuesta no es JSON válido, se considera rechazada.

Guardrail didáctico

La validación es pedagógica. No garantiza que un LLM nunca invente información, pero sí que la aplicación rechace respuestas peligrosas.

  • JSON válido
  • campos `explicacion` y `accion` presentes
  • decisión no cambia
  • no introduce números distintos de los datos permitidos
  • sin términos prohibidos como “gases tóxicos”, “contaminación” o “toxicidad”
  • acción compatible con la decisión

Fallback determinista

EXPLICACIÓN SEGURA
El dispositivo compostera-cf-01 registra 48 °C y 60 % de humedad.
La decisión del sistema es REVISAR_TEMPERATURA.

ACCIÓN
Una persona debe revisar la temperatura del dispositivo.

Si Ollama falla o su respuesta no supera la validación, se usa este texto.

Modo sin IA

La práctica incluye --sin-ia para mostrar que el sistema sigue funcionando sin modelo generativo:

python explicar_decision.py --demo --sin-ia

Esto refuerza la idea de que la IA es una capa de explicación y no un sustituto del criterio técnico.

Diferencias entre tecnologías

POSTGRESQL -> historial
MQTT -> transporte de mensajes
FIWARE -> contexto actual interoperable
LangGraph -> organiza decisiones y flujos
Ollama/LLM -> genera lenguaje natural

El LLM no sustituye a la base de datos, al broker ni al flujo determinista. Solo explica el resultado ya decidido.

Mini-reto

  1. Ejecuta python explicar_decision.py --demo --sin-ia.
  2. Ejecuta python explicar_decision.py --demo con Ollama activo.
  3. Compara las salidas.
  4. Prueba una respuesta inválida y observa el fallback.
