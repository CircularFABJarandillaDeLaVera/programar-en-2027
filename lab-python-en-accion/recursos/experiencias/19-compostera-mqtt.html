DESCARGAR PRÁCTICA

Primero aparece la necesidad: ¿qué ocurre cuando los datos los genera continuamente una máquina o un sensor? Todavía no tenemos sensor físico; primero simularemos el dispositivo con Python.

La necesidad

Hasta ahora los datos han venido de formularios, usuarios, aplicaciones y bases de datos. Ahora queremos ver datos pasando en tiempo real de un proceso Python a otro a través de un broker.

SIMULADOR PYTHON
temperatura + humedad
        ↓ publica
      MQTT
        ↓ distribuye
    MOSQUITTO
        ↓ entrega
MONITOR PYTHON

Mosquitto es el intermediario que recibe mensajes y los entrega a quienes están suscritos.

Tres conceptos

  • PUBLICADOR: el simulador envía las lecturas.
  • TOPIC: la dirección lógica donde se publican.
  • SUSCRIPTOR: el monitor escucha y recibe los mensajes.

El monitor escucha circularfab/dispositivos/+/telemetria. El comodín + acepta cualquier dispositivo_id en ese nivel.

Contrato de datos

{
  "dispositivo_id": "compostera-cf-01",
  "temperatura_c": 36.8,
  "humedad_pct": 62
}

Usamos dispositivo_id para que el mismo contrato sirva más adelante para otros dispositivos.

Topic de esta demostración:

circularfab/dispositivos/compostera-cf-01/telemetria

Deja que aparezca la tecnología

El simulador publica una secuencia de demostración plausible de temperatura y humedad. No es un modelo científico del proceso de compostaje.

COMPOSTERA CF-01
Temperatura: 33.9 °C
Humedad: 66 %
Publicando en MQTT...

El monitor valida mínimamente el JSON y muestra cada lectura recibida.

MENSAJE RECIBIDO
Dispositivo: compostera-cf-01
Temperatura: 33.9 °C
Humedad: 66 %

Tres tecnologías, tres problemas

POSTGRESQL
→ conserva histórico

MQTT
→ transporta mensajes entre dispositivos y aplicaciones

FIWARE
→ representa contexto actual e interoperable

En esta experiencia no conectamos MQTT con FIWARE. Cada tecnología resuelve aquí un problema diferente.

Ejecutar la práctica

  1. Descomprime la práctica y crea/activa un entorno Python si corresponde.
  2. Instala la dependencia: pip install -r requirements.txt.
  3. Levanta Mosquitto: docker compose up -d.
  4. Terminal A: python monitor_compostera.py.
  5. Terminal B: python simulador_compostera.py.
  6. Al terminar: docker compose down.

allow_anonymous true y persistence false son decisiones solo para este laboratorio local. No son configuración de producción.

Mini-reto

Cambia en el simulador:

dispositivo_id = "compostera-cf-01"

por:

dispositivo_id = "compostera-cf-02"

Comprueba que el mismo monitor recibe el nuevo dispositivo. Así se entiende por qué usamos un identificador genérico y un topic reutilizable.
