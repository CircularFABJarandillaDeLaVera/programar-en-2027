DESCARGAR PRÁCTICA

Objetivo: automatizar desde Python la actualización de contexto que antes hacíamos manualmente en Orion-LD.

La nueva necesidad

Hasta ahora actualizábamos Orion-LD manualmente. Pero cuando una persona ficha, nadie debería tener que abrir PowerShell.

Mensaje mostrado:

Fichaje registrado. Hay un problema temporal actualizando el estado compartido.

No podemos decir "el fichaje ha fallado" porque sería falso.

Dos sistemas

Una misma acción puede afectar a dos sistemas. Eso no significa que ambos tengan que tener siempre el mismo resultado.

PostgreSQL:
último evento = ENTRADA

Orion-LD:
lastEvent = SALIDA

El histórico podía estar correcto mientras el contexto publicado quedaba desactualizado. No fue un ejemplo inventado: ocurrió durante la validación.

Recuperación

Después se volvió a arrancar Orion-LD. El siguiente fichaje válido hizo una nueva actualización y ambos sistemas volvieron a coincidir.

Eso no reconstruye automáticamente todos los posibles estados perdidos. Simplemente el nuevo evento vuelve a publicar el contexto vigente.

Una reconciliación real podría construirse posteriormente desde PostgreSQL, pero no se implementa aquí.

Validación real

PRÁCTICA

  1. Levanta PostgreSQL como en las experiencias anteriores.
  2. Levanta Orion-LD y MongoDB con el Compose de la Experiencia 17.
  3. Copia .env.example a .env.
  4. Configura ORION_LD_URL=http://localhost:1026.
  5. Ejecuta python -m unittest -v test_api.py.
  6. Arranca FastAPI con uvicorn main:app --reload.
  7. Crea un trabajador desde /app/empresa/.
  8. Inicia sesión en /app/fichar/.
  9. Registra ENTRADA y consulta Orion-LD.
  10. Registra SALIDA y consulta Orion-LD de nuevo.
