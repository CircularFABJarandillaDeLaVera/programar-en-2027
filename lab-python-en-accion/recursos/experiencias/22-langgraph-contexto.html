DEL CONTEXTO A UNA DECISIÓN

DESCARGAR PRÁCTICA

FIWARE ya nos da contexto actual. Ahora convertimos ese estado en un proceso con decisiones y rutas condicionales.

Necesidad antes de tecnología

La empresa puede consultar el estado del dispositivo, pero no basta con leerlo. Lo importante es decidir según ese contexto.

contexto actual
     ↓
  decisión
     ↓
resultado observable

En este caso la decisión es didáctica y determinista, no científica ni agronómica. Las reglas son para aprender rutas condicionales.

¿Por qué LangGraph?

Este ejemplo también podría hacerse con funciones y if/else. La razón pedagógica de usar LangGraph aquí es mostrar muy claramente:

  • estado
  • nodo
  • transición
  • ruta condicional

La necesidad aparece antes que la tecnología: primero queremos decidir según el contexto del dispositivo, y entonces LangGraph organiza ese proceso con un grafo claro.

add_conditional_edges hace exactamente eso: después de evaluar_estado, el sistema mira el estado actual y elige el siguiente nodo según una regla determinista.

Arquitectura del flujo

START
↓
obtener_contexto
↓
validar_datos
↓
evaluar_estado
↓
add_conditional_edges
datos_incompletos / revisar_temperatura / revisar_humedad / sin_revision
↓
END

Reglas didácticas

Estas reglas son ficticias para aprender rutas condicionales. No son recomendaciones reales del compostaje.

  • si falta temperatura o humedad: DATOS_INCOMPLETOS
  • si temperatura_c >= 45: REVISAR_TEMPERATURA
  • si humedad_pct < 50: REVISAR_HUMEDAD
  • en otro caso: SIN_REVISION_PRIORITARIA

Mini-reto

Cambia solo datos_contexto_demo.json con temperatura alta, ejecuta en modo demo y comprueba que la ruta cambia a revisar_temperatura.

Luego prueba humedad baja y observa revisar_humedad. El grafo sigue igual y el cambio lo hace el dato.

Diferencias entre tecnologías

POSTGRESQL -> guarda histórico
MQTT -> mueve mensajes
FIWARE -> representa contexto actual interoperable
LANGGRAPH -> organiza un proceso con estado y decisiones

LangGraph no sustituye a FIWARE ni es un broker. Solo organiza la decisión.

Ejecución

  1. Instala dependencias: pip install -r requirements.txt.
  2. Modo real: python flujo_contexto.py.
  3. Modo demo: python flujo_contexto.py --demo.
  4. Ejecuta tests: pytest -q.
